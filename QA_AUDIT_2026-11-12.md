# Pause public-site QA and UX audit

Audited on 2026-11-12. Target: [Pause on GitHub Pages](https://jyotiraditya21-bug.github.io/pause-stress-mvp/). Public pages only; no credentials. This report distinguishes the deployed site I inspected from the local QA branch containing fixes.

## 5-line summary

Pause is a React 19 + Vite single-page camera check-in hosted as a static GitHub Pages site.
The visible Calm index is a fixed facial-geometry calculation; a separate MobileNet model is an optional acted-expression comparison.
Scan processing and optional history are browser-local; the scanned camera stream is not saved or uploaded by default.
The deployed site communicates that the score is experimental and not a clinical stress measurement.
Four user-facing issues were reproduced twice; fixes and regression checks are committed and pushed on branch `qa-audit-2026-11-12` and are not yet live.

## 2. PAGE STRUCTURE AND LAYOUT

### Screens/routes, exact visible order

The deployed app is a single HTML page. Navigation switches screen state in-place; the screen order below describes rendered content, not separate server routes.

| Screen | Top-to-bottom content; tags and layout |
|---|---|
| First-use welcome | `header.site-header` with Pause brand and nav; `main.page.onboarding` with one `h1`, explanatory `p`, Continue button; footer. First-use state is browser-local. |
| Scan/home | Header; optional notice/recovery banner; optional guided-study panel when `study=1&policy=prospective-1`; `main.scan-screen` CSS Grid: left `div.scan-story` (intro, instructions, privacy note), right `section.scan-card` (duration, camera circle, status, Start); disclaimer and feature/evidence sections below; footer. |
| Result | Header; `main.result-screen` / score card; score/band and scan graph or a no-score failure explanation; retry, save, history, or calibration actions; optional diagnostics disclosure when `diagnostics=1`; footer. Result exists in in-memory SPA state and is not a durable deep link. |
| History | Header; `main.page.history-page`; heading/export; empty-state panel or grouped trends and a list of saved scans with view/delete buttons; footer. |
| Settings | Header; `main.page.settings`; panels in order for personal baseline, optional acted-expression model switch, recovery backups; footer. |
| Credibility | Header; `main.page.info-page`; plain-language product status, capability and limits panels; footer. |
| Evidence & metrics | Header; `main.page.info-page.evidence-page`; explanation, three metric cards, evidence scope, and list of unestablished claims; footer. |
| Privacy | Header; `main.page.info-page`; one-column privacy text; footer. |
| About this index | Footer action opens `main.page.info-page`; explanation of formula, model, confounds and non-diagnostic status. |
| Lab | Only with `lab=1`; `main.page.lab-page` and embedded `Experiment` content. It is not a normal nav item for public users. |

### Main flows

1. **First use:** open the Pages URL → Continue to scan → explicitly press Start → grant camera permission in the browser → center face / 10-second capture → receive a numeric result or a failure with retry guidance.
2. **Repeat scan:** result → Scan again → new independent scan; the app does not reuse the previous score as the current score.
3. **Optional baseline:** Settings or result → Calibrate when calm → camera scan → save a baseline locally → later scans compare with that baseline. This is optional, not required for the generic index.
4. **Optional history:** result → Save this result → History → view/export/delete. Saved data stays in this browser profile. Delete confirmation is now added on the QA branch.
5. **Optional guided study:** open `?study=1&policy=prospective-1` → choose pseudonym/task → press Begin (consents to local derived-record saving) → scan A → wait for repeat window → scan B → download local study log. The audit did not begin a pair, scan, or save study records.

## 4. FEATURES AND FUNCTIONALITY

| Feature | Implementation and behavior |
|---|---|
| Camera check-in | `CameraScan.jsx` requests the camera only after Start. It loads local MediaPipe assets, processes frames locally, draws a mirrored preview/landmark overlay, and stops the stream on cancel, completion, failure, unmount, or hidden page. The public scan is intended to take 10 seconds after the camera is ready. |
| Face features and score | `liveIndex.js` aligns 478 landmarks to a canonical face and derives eye aspect ratio, mouth-open ratio, lip press, brow furrow, lip-corner angle, and jaw ratio. The generic reference uses brow furrow, lip press, and lip corner; personal-baseline mode adds jaw clench. Per-feature standardized deviations use a sigma floor and are clipped to `[-3,3]`. Combined `r = sum(z)/sqrt(n)` is passed through a sigmoid and reversed to a 0–10 Calm index. ScanReliability groups samples into 0.2-second slots and one-second windows, calculates a median score, and rejects conflicting/insufficient results. Quality gates are engineering heuristics, not biological validation. |
| Optional neural comparison | `mlInference.js` / `modelRunner.js` use a locally bundled MobileNetV3-Large ONNX model and ONNX Runtime Web. It is a separate acted calm/neutral vs anger/fear comparison. It does not set the visible geometry score. Failure falls back to geometry. User can turn it off in Settings; preference is browser-local. |
| Personal baseline | Optional calibration scan creates a browser-local baseline (feature medians/MAD statistics); future comparisons use that reference. It does not establish a diagnosis or validated personal stress scale. |
| Result graph | `ResultCard.jsx` shows per-second score values and missing gaps; a failed scan shows no invented score and gives a retry action. Variation range is identified as within-scan variation, not a confidence interval. |
| History | Explicit Save stores derived scan result in `localStorage`; History groups compatible scans, displays a trend and timestamps, supports JSON export and delete. Data stays in this browser profile and is not encrypted. |
| Guided local study | Query-gated component allows participant pseudonym and task selection and saves derived scores, quality, failures and task labels only after Begin consent. It does not record video or landmarks. The QA branch adds a 64-character field limit. |
| Info screens | Credibility, Evidence, Privacy, About explain index, metrics, privacy and limitations. |

### Score formula excerpt (generic reference)

From `frontend/src/liveIndex.js`:

```js
const sigma = Math.max(rawSigma, 0.05 * Math.abs(mu) + 1e-3);
const z = clamp((feature - mu) / (sigma + 1e-6), -3, 3);
const r = sum(zValues) / Math.sqrt(zValues.length);
const calmIndex = 10 * (1 - sigmoid(r));
```

The code computes the feature statistics from a fixed constructed generic reference, or from an optional personal baseline. This output is not labeled as a stress probability or clinical measurement.

## 6. CURRENT METRICS AND TRUST ELEMENTS

- Landing page and Evidence/Settings display **ROC-AUC 0.906 (95% CI 0.860–0.959), accuracy 79.39%, balanced accuracy 78.88%**, from six actor-separated source checkpoints evaluated on 1,344 RAVDESS videos.
- Copy explicitly states labels were acted calm/neutral vs anger/fear, those values are not stress accuracy, and the averaged shipped model has not been independently evaluated on untouched external data.
- The geometric index is stated to be experimental, unable to determine felt stress, not diagnostic, and affected by lighting, angle, expression, movement, and face shape.
- Privacy text says camera processing occurs on-device, no video/audio/landmarks are uploaded or stored by default, optional study data is separately consented, local history is not encrypted, and the host receives ordinary asset requests/logs.
- Footer: “A private moment. A little more awareness.” Links to Privacy and About.
- Not present: testimonials, research citations on the main app, contact/support address, clinical validation, stress-specific accuracy/ROC, evidence for 5–10-minute score repeatability, or subgroup robustness. The app’s existing caveats correctly say these have not been established.
- Main credibility gap: dataset expression-class metrics may be mistaken for product stress accuracy unless the separate-experiment label remains prominent wherever the values appear. Current copy does separate them.

- Keyboard focus outline is defined globally; buttons generally have ≥44px height; inputs/selects in guided study are 44px; reduced-motion disables animations.
- Automated axe checks ran on home, result and History states; no serious/critical violations were found. It was not a full WCAG certification.

## 9. CODE QUALITY NOTES

- React/Vite structure is compact, but `main.jsx` owns many concerns: navigation, local storage, settings, history and result orchestration. Splitting state/navigation into a small router/context would reduce coupling.
- Scoring and capture are separated into `liveIndex.js`, `scanReliability.js`, `scanMetrics.js`, and `CameraScan.jsx`, with unit tests. This is a useful boundary to preserve.
- Several historical modules remain in the frontend tree but are not mounted by the Pages SPA: `Questionnaire.jsx`, `Guidance.jsx`, and `api.js`. They can confuse maintainers about what is live; label as legacy/local backend mode or remove in a separately reviewed cleanup.
- Frontend UI uses many literal colors in addition to CSS variables; consolidate repeated color values into tokens when doing future design work.
- The optional model metrics refer to source checkpoints, while the shipped averaged artifact is not independently evaluated. Existing copy explains this; keep that distinction next to every reuse of the metrics.
- The study panel is opened by a query flag and stores derived study data in localStorage. It is a convenience research tool, not a secure participant-management system; do not put names or sensitive data there.
- No auth, roles, server-side protected records, pricing, checkout, or user-to-user data access exist in the audited public flow. URL flags expose UI modes but are not access controls and should not be treated as such.
- Changes likely to affect science/product meaning: `liveIndex.js`, `scanReliability.js`, reference/config JSON, result interpretation, and model-data/provenance copy. Any such change needs separate versioning and validation; this audit did not change the score formula, gates, weights, model, or data.
